# Operit 记忆库 → Eta 移植设计

> 编写日期：2026-10-24
> 目标仓库：`projects/eta-source`，分支 `feat/memory-spaces`
> 参考实现：`AAswordman/Operit`（LGPL-3.0），本地参考副本在会话临时目录，不入库
> 原则：**按设计重写，不直接拷贝源码**（Eta 为 PolyForm Noncommercial，许可证不兼容）

## 一、目标

用 Operit 的记忆库模型替换 Eta 现有的 `MEMORY.md` 单文件记忆：

- 结构化记忆条目（标题/正文/标签/重要性/来源/时间）
- 多记忆空间，支持角色绑定（隔离 + 共享）
- 检索式取用，替代"核心段 + 标题索引"全量注入
- 自动保存（回复定稿后提取候选）
- 保留可导出、可备份、可人工编辑的能力

## 二、Operit 实现分析

### 2.1 数据模型

| 实体 | 关键字段 | 说明 |
|---|---|---|
| `Memory` | id, uuid, title, content, contentType, source, credibility, importance, folderPath, embedding, createdAt/updatedAt/lastAccessedAt | 一条独立记忆 |
| `MemoryTag` | id, name, 父子关系 | 层级标签 |
| `MemoryProperty` | 记忆的键值对属性 | 扩展元数据 |
| `MemoryLink` | source, target, type, weight, description | 记忆间有向关系，支持 backlinks |
| `DocumentChunk` | 所属 memory、块序号、内容、embedding | 长文档分块 |
| `MemorySpace` | id, name, profileAutoUpdateEnabled/Locked | 独立记忆数据库 |

空间存储在 `UserPreferencesManager`：`memorySpaceListFlow` + `activeMemorySpaceIdFlow`。
角色卡通过 `memoryProfileBindingMode` 绑定：
- `FOLLOW_GLOBAL`：跟随当前激活空间
- `FIXED_PROFILE` + `memoryProfileId`：固定使用某个空间

### 2.2 检索

入口 `MemoryRepository.searchMemories(query, ...)`：

1. **关键词解析**：`|` 或空格分隔；词内 `*` 为通配；`*` 单独使用返回全部
2. **中文扩展**：Jieba 分词切碎长词，提高中文召回
3. **四路候选**：
   - 关键词：标题/正文/标签字面匹配 + 通配正则
   - 标签：标签片段查询
   - 语义：向量索引（`VectorIndexManager`，按维度分文件，支持增量重建）
   - 链接：沿 `MemoryLink` 扩展邻居，权重衰减
4. **打分**：
   - RRF 基础分 `1 / (K + rank)`
   - 关键词覆盖率加成
   - 语义分 × √importance
   - 三种模式：`BALANCED` / `KEYWORD_FIRST` / `SEMANTIC_FIRST`，各给关键词/语义/链接不同倍率
5. **阈值与条数**：`threshold` 最小相关度，`limit` 默认 20，>20 只返回标题与截断正文

### 2.3 注入策略（关键）

**记忆不进入系统提示。** `SystemToolPrompts.kt` 里记忆只是工具分类：

```
Memory and Memory Library Tools
  - query_memory
  - get_memory_by_title
```

系统提示与工具定义是静态文本，记忆正文只作为工具结果追加到历史末尾。因此
prompt 前缀天然稳定，**不存在缓存击穿问题**。

配套机制：
- `snapshot_id`：同一快照内已返回的记忆不再重复返回，每空间最多 32 个快照
- 自动保存发生在回复定稿之后，不参与本轮 prompt

### 2.4 自动保存

`MemoryAutoSaveScheduler`：

- 60 秒 tick，按空间轮询
- 候选表 `MemoryAutoSaveCandidate`：`pending` / `processing` / `failed`，带 `attemptCount`、`lastError`
- 触发来源：回复定稿（`reply_finalized_auto`）、用户选中消息
- 单批最多 48 条消息、20 个候选，少于 5 条候选不触发提取

`MemoryLibrary.saveMemory`：

1. 清理工具输出与思考内容（只保留结论）
2. 拼分析输入：问题 + 解决方案（截断 3000 字）+ 最近 10 条历史（每条截断 4000 字）
3. 调 AI 返回 JSON：`main` / `new` / `update` / `merge` / `links` / `profile_markdown`
4. 应用变更：新增、更新（可信度/重要性）、合并、建链
5. 另有自动分类：未分类记忆每批 10 条，AI 归入文件夹

### 2.5 工具清单

`create_memory`、`update_memory`、`delete_memory`、`move_memory`、
`link_memories`、`query_memory`、`get_memory_by_title`、
`query_memory_links`、`update_memory_link`、`delete_memory_link`

| `MemoryTag` | `MemoryTagEntity` + CrossRef | 层级用 parentId |
| `MemoryProperty` | `MemoryPropertyEntity` | |

| `MemorySpace` | `MemorySpaceEntity` | |

## 四、关键决策

1. **ORM 用 Room**：不引入 ObjectBox，避免第二套数据层。
2. **注入改零注入**：删除 Eta 现有的核心段/标题索引自动注入，只保留工具描述。
   可选保留一条「核心摘要」注入，默认关闭，供不想每次查询的场景使用。
3. **向量第一版不做**：没有可用 embedding 服务；字段、接口、检索权重先预留。
   检索先做关键词 + 标签 + 链接三路。
4. **中文分词**：Operit 用 Jieba。Eta 第一版用简单的二元切分 + 字面匹配，
   后续可引入轻量分词库（注意包体积）。
5. **自动保存走 Eta 现有 run 生命周期**：在 Agent Loop 结束、结果落库后触发，
   复用 `AgentRunArchiveStore` 的会话数据，不额外扫数据库。
6. **旧数据迁移**：解析 `MEMORY.md` 的 `#`/`##` 标题成条目，正文保留；
   原文件改名 `MEMORY.md.bak` 留在原目录，不做删除。
7. **角色隔离**：每个角色首次进入角色会话时自动创建 `character:<id>` 空间；
   角色卡可选「跟随全局」以共享工作记忆。
8. **备份**：`EtaBackupValidation` 增加记忆库导出格式，`MEMORY.md` 字段保留兼容。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 删除自动注入后角色"不知道有什么" | 工具描述里写清用法；提供 `query_memory("*")` 列出全部 |
| 检索质量不如预期 | 保留可调权重；先做关键词优先模式 |
| UI 工作量大 | 先用最小可用界面（列表 + 编辑 + 空间切换），图谱后置 |
| 作者更新导致合并冲突 | 改动集中在新增文件 + 少量接入点，降低冲突面 |
| 许可证 | 只借鉴设计，不复制代码；文档注明来源 |

## 七、与现有 Eta 记忆的关系

- `AgentMemoryRepository` / `AgentMemoryStore`：保留为"导入导出适配层"，P6 后不再作为主存储
- `ConversationMemoryPins`：随注入逻辑一起移除
- 角色剧情记忆：迁移为角色的固定记忆空间，`character_memory_*` 工具改为空间别名
- `memory_get` / `memory_write`：保留工具名做兼容，内部转发到新记忆库

### 与世界书实现的核对

Operit 的世界书只有数据模型（`TavernCharacterBook` / `TavernBookEntry`）和导入导出，
**没有运行时投影逻辑**。Eta 现有的 `CharacterWorldbook` 已经完整支持：
scan_depth、token_budget、recursive_scanning、selective + secondary_keys、constant、
position（before/after）、priority、insertion_order、大小写敏感，以及对不支持特性的显式拒绝
（`CharacterWorldbookSupport`）。**世界书方向无需从 Operit 反向适配。**

### 本轮补齐的记忆库能力

| 能力 | 实现 |
|---|---|
| 链接查询/更新/删除 | 新增 `query_memory_links`、`update_memory_link`、`delete_memory_link` 工具 |
| 条目合并 | `MemoryAnalysisPlan.merges`；合并后删除源条目，避免重复 |
| 文档导入分块 | `MemoryRepository.importDocument` + `create_memory_document` 工具，按 `chunk_size` 写入 `memory_chunks` |
| 未分类自动归档 | `MemoryFolderClassifier` + `LlmMemoryFolderClassifier`（复用对话模型）；调度器每轮对未分类条目归档，无候选时不调模型 |

### 仍需注意

- 向量检索已内置 `OpenAiEmbeddingProvider`：直接复用**当前对话模型**的 baseUrl 与 apiKey，不需要额外配置。
  模型名先查服务商 `/models` 里带 `embed` 的项，找不到回退 `text-embedding-3-small`；
  服务商不支持 embedding 时自动降级为关键词/标签/链接检索，不影响使用。
- 未配置 provider 时 `vectorWeight` 自动归零，行为与纯关键词检索一致。
- 备份测试剩余的 2 个失败（`cleanupFailureReports...` 的 `SQLITE_CANTOPEN`、
  `malformedOrLateInvalidRecords...` 的旧记忆为空）在基线代码上同样存在，属于 Robolectric 环境问题。
